# Focus Timer on React

`Focus Timer on React` - это SPA-приложение на `React` + `Vite` для фокус-сессий в формате `Pomodoro` с музыкальным блоком, переключением режимов `Work / Break`, настройкой количества циклов, локальным сохранением пользовательских параметров и добавлением собственных треков через локальный API.

Проект был не просто "собран", а переработан в более взрослую структуру: логика разделена на независимые компоненты, код переведен на `ES Modules`, а стили из глобального подхода вынесены в `CSS Modules`. За счет этого приложение стало проще поддерживать, расширять и использовать как полноценный учебный кейс для портфолио.

## Что это за проект

Приложение помогает пользователю работать короткими фокус-интервалами и переключаться между работой и отдыхом без ручного контроля времени. Внутри одного интерфейса объединены:

- таймер обратного отсчета;
- режимы `Work` и `Break`;
- счетчик завершенных циклов;
- выбор лимита циклов;
- аудиоплеер с фоновым `lo-fi`;
- переключение и просмотр треков;
- форма добавления нового трека;
- сохранение данных между перезагрузками.

## Цели переработки проекта

На этапе рефакторинга задача была не только "чтобы работало", а чтобы проект выглядел как аккуратное модульное frontend-приложение.

Что было сделано по архитектуре:

- код разбит на отдельные React-компоненты по зонам ответственности;
- проект полностью работает через `import/export`, то есть переведен на `ES Modules`;
- стили каждого интерфейсного блока вынесены в отдельные `CSS Modules`;
- повторно используемая кнопка собрана в универсальный компонент `Button`;
- логика таймера, переключения режимов, циклов и воспроизведения музыки централизована в `FocusTimer`;
- выбор циклов сохраняется в `localStorage`;
- список треков загружается через `fetch` из локальной базы `json-server`;
- новые треки добавляются через `POST`-запрос в локальную БД;
- UI разделен на изолированные блоки, чтобы уменьшить связность между стилями и компонентами.

## Что именно было улучшено

Если описывать проект как кейс для резюме или портфолио, ключевая работа здесь была такой:

- выполнен рефакторинг интерфейса из более монолитного состояния в компонентную структуру;
- внедрена модульная организация стилей вместо опоры на глобальные CSS-классы;
- настроена изоляция визуальных состояний кнопок через `clsx` и `CSS Modules`;
- реализовано хранение пользовательских настроек в браузере;
- добавлена интеграция с локальным API для загрузки и создания треков;
- улучшена масштабируемость проекта: теперь UI можно расширять по компонентам, а не переписывать один большой файл;
- подготовлена структура, которая ближе к реальным production-подходам, чем к учебному "все в одном месте".

## Измеримые результаты рефакторинга

- для интерфейса используются `8` отдельных файлов `CSS Modules`;
- основной сценарий приложения покрывает таймер, циклы, музыкальный блок, список треков и форму добавления в рамках одной SPA;
- проект использует `3` уровня хранения/источников данных:

## Основной функционал

- запуск и остановка таймера одной кнопкой;
- отображение текущего режима `Work / Break`;
- автоматическое переключение между рабочей и перерывной сессией;
- подсчет завершенных циклов;
- ограничение количества циклов от `1` до `4`;
- сохранение выбранного количества циклов после перезагрузки страницы;
- воспроизведение фоновой музыки;
- перемотка трека на `5 секунд` вперед и назад;
- управление громкостью через `range`-слайдер;
- просмотр списка доступных треков;
- выбор активного трека в интерфейсе;
- добавление нового трека через форму;
- отправка нового трека в локальную базу данных.

## Как работает приложение

После запуска приложение открывается в режиме `Work`.

Пользователь может:

- запустить таймер;
- остановить таймер;
- выбрать количество циклов;
- открыть список треков;
- выбрать нужный трек;
- открыть форму и добавить новый трек.

При активном таймере:

- каждую секунду уменьшается значение времени;
- при наличии выбранного трека запускается аудио;
- после завершения `Work`-сессии приложение переключается на `Break`;
- после завершения `Break` увеличивается счетчик пройденных циклов;
- при достижении лимита цикл останавливается и состояние сбрасывается к стартовому режиму.

## Архитектура компонентов

### `App.jsx`

Минимальная точка композиции приложения. Подключает главный компонент `FocusTimer`.

### `FocusTimer.jsx`

Главный контейнер приложения и центр бизнес-логики. Компонент отвечает за:

- состояние таймера;
- состояние режима `Work / Break`;
- управление запуском и остановкой;
- хранение и смену количества циклов;
- счетчик завершенных циклов;
- управление открытием списка треков и формы;
- загрузку треков через `fetch`;
- создание новых треков через `POST`;
- управление воспроизведением через `audio` и `useRef`;
- сохранение пользовательских настроек в `localStorage`.

## Источники данных

Проект использует несколько источников данных одновременно.

### `React state`

Используется для:

- времени;
- статуса таймера;
- режима;
- списка треков;
- открытых панелей;
- выбранного трека.

### `localStorage`

Используется для сохранения количества циклов, чтобы настройка не сбрасывалась после перезагрузки страницы.

### `json-server`

Используется как локальная база треков. Данные читаются по адресу:

`http://localhost:3001/trcks`

Туда же отправляются новые треки через `POST`.

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/Canzas-91/Focus-Timer-on-React
```

### 2. Перейти в папку проекта

```bash
cd Focus-Timer-on-React
```

### 3. Установить зависимости

```bash
npm install
```

### 4. Запустить frontend

```bash
npm run dev
```

### 5. Запустить локальный сервер с треками

Во втором терминале:

```bash
npm run server
```

После этого:

- интерфейс будет доступен через `Vite`;
- локальная база треков будет доступна на `http://localhost:3001/trcks`.

## Скрипты

- `npm run dev` - запуск dev-сервера `Vite`;
- `npm run build` - production-сборка проекта;
- `npm run preview` - локальный предпросмотр production-сборки;
- `npm run lint` - проверка проекта линтером;
- `npm run server` - запуск `json-server` на порту `3001`.
